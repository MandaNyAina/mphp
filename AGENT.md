# AGENT.md: working in an M-PHP project

Instructions for an AI coding agent (or a new developer) using this repository as a framework template.
Read this file first; the rest of the code base is small enough to read directly.

## What this is

M-PHP is a small PHP 8.4+ framework with a Svelte 5 + TypeScript front end. **PHP is the source of truth**:
TypeScript types, the route helper and the API client are *generated* from PHP classes and attributes.
No Node.js runs in production; there is no ORM, no template engine, and no runtime dependency (`core/autoload.php` replaces Composer's autoloader).

## Commands you will use

```bash
php bin/mphp dev                    # PHP server + Vite hot reload (needs a real terminal)
php bin/mphp serve [--port=8000]    # PHP server only
php bin/mphp routes                 # list routes (name, handler, middleware)
php bin/mphp make:controller Post   # app/Controllers/PostController.php
php bin/mphp make:model Post        # app/Models/Post.php
php bin/mphp make:migration create_posts_table
php bin/mphp migrate | migrate:rollback | migrate:status
php bin/mphp types:generate         # REQUIRED after changing routes, app/Data or FormRequests
php bin/mphp key:generate           # writes APP_KEY into .env
php bin/mphp build                  # types + vite build + route cache
php bin/mphp package                # dist/release.zip
php bin/mphp compile                # dist/mphp.phar (single file)

vendor/bin/pest                     # PHP tests (composer test)
npm run check                       # TypeScript + Svelte type check
npm run build                       # production front end -> public/build
```

First run: `composer install && npm install && cp .env.example .env && php bin/mphp key:generate && php bin/mphp migrate`.

## Map of the project

| Path | Purpose | Edit it? |
|---|---|---|
| `app/Controllers` | Controllers. Routes are PHP attributes on methods | yes |
| `app/Models` | `Mphp\Database\Model` subclasses | yes |
| `app/Data` | Output DTOs (`final readonly class`), become TypeScript interfaces | yes |
| `app/Requests` | `FormRequest` classes: validated + typed request bodies | yes |
| `config/*.php` | App and database config, values come from `.env` via `env()` | yes |
| `database/migrations` | Migrations returning `new class extends Migration` | yes |
| `resources/pages/*.svelte` | One Svelte page per file, mounted by `$view->page('Name', $props)` | yes |
| `resources/js/lib` | `api.ts` (typed client), `form.svelte.ts` (`Form` helper) | rarely |
| `resources/js/generated/*.ts` | **Generated.** Never edit by hand; run `types:generate` | no |
| `resources/views` | PHP templates: page shell, error pages, debug bar | rarely |
| `public/` | The only web root. `public/build` is generated by Vite | no |
| `core/` | The framework (`Mphp\` namespace) | only when changing the framework itself |
| `storage/` | Logs, cache, uploads, SQLite file. Git-ignored | no |
| `tests/` | Pest tests (`tests/Unit`, `tests/Feature`) | yes |

## Recipe: add a feature end to end

Example: a `Post` resource. Do the steps in this order.

1. **Migration**: `php bin/mphp make:migration create_posts_table`, then fill `up()`/`down()` using `$db->statement(sprintf('CREATE TABLE posts (%s, title VARCHAR(100) NOT NULL)', $db->idColumn()))`. `idColumn()` keeps it portable across SQLite/MySQL/PostgreSQL. Run `php bin/mphp migrate`.
2. **Model**: `app/Models/Post.php` with `protected static string $table = 'posts';` and an explicit `protected static array $fillable = ['title'];`. Without `$fillable`, `create()`/`update()` throw by design.
3. **Output DTO**: `app/Data/PostData.php`, a `final readonly class` with typed public constructor properties and a `fromModel()` factory. For arrays add `#[Ts('PostData[]')]`.
4. **Input**: `app/Requests/PostInput.php` extending `FormRequest`, one promoted constructor property per field, each with `#[Rule('required|string|max:100')]`.
5. **Controller**: `app/Controllers/PostController.php`.

   ```php
   #[Prefix('/api/posts')]
   final class PostController
   {
       #[Get(name: 'posts.index')]
       #[Ts('PostData[]')]
       public function index(): array { return array_map(PostData::fromModel(...), Post::all()); }

       #[Post(name: 'posts.store')]
       #[Ts('PostData')]
       public function store(PostInput $input): Response
       {
           return Response::json(PostData::fromModel(Post::create($input->toArray())), 201);
       }

       #[Delete('/{id:\d+}', name: 'posts.destroy')]
       #[Ts('void')]
       public function destroy(int $id): Response
       {
           (Post::find($id) ?? throw new HttpException(404, 'Post not found.'))->delete();
           return Response::noContent();
       }
   }
   ```
6. `php bin/mphp types:generate`: `PostData`, `RouteBodies['posts.store']`, `RouteResponses[...]` now exist in `resources/js/generated/`.
7. **Front end**: add `resources/pages/Posts.svelte` and render it from a controller with `$this->view->page('Posts', new PostsProps(...))` (a DTO in `app/Data`). Call the API with `api('posts.store', { body: { title } })` or, for forms, `new Form('posts.store', { title: '' })` (gives `form.errors.title`, `form.processing`, `await form.submit()`).
8. **Tests** (see below), then run `vendor/bin/pest` and `npm run check` and `npm run build`.

## Conventions and facts that are easy to get wrong

- **Every PHP file** starts with `declare(strict_types=1);`. Classes are `final` unless designed for extension. Use `readonly` for DTOs.
- **Route attributes**: `#[Get]`, `#[Post]`, `#[Put]`, `#[Patch]`, `#[Delete]` take `(path, name:, middleware:)`; class-level `#[Prefix('/api/x', middleware: [...])]`. Path params: `{id}` or with a constraint `{id:\d+}`. Always set `name:` on routes the front end calls: only named routes are generated for TypeScript.
- **Action return values**: `Response` as is; array/object becomes JSON 200; string becomes HTML; `null` becomes 204. Parameters are injected by type (`Request`, any service, a `FormRequest`) or by name (route params, cast by declared `int`/`float`/`bool`).
- **Closure routes** (`$router->get(...)` in `routes/web.php`) work, but they prevent `routes:cache`, the PHAR and `package` from caching routes. Prefer controller attributes.
- **Validation** rules: `required nullable string integer numeric boolean email url array date in:a,b regex:/x/ min:n max:n`. `min`/`max` measure length for strings, value for numbers, count for arrays. Unknown rule names throw (typos are caught). A pipe inside a regex needs the array form: `#[Rule(['regex:/a|b/'])]`.
- **Middleware**: global list in `config/app.php` (`'middleware' => ['csrf']`), per route via `middleware: ['throttle:30,60']`. Custom middleware implements `Mphp\Http\Middleware`.
- **Database**: only `Connection`/`QueryBuilder`/`Model`. Values are always bound parameters; identifiers are validated. `update()` and `delete()` without `where()` throw. Never concatenate user input into SQL; if you need raw SQL, use `$db->select($sql, [$bound])`.
- **HTML output**: always `e()` in PHP templates. Svelte escapes by default; never use `{@html}` with user data.
- **Strict CSP** (`script-src 'self'; style-src 'self'`): no inline `<script>`, no inline `style=""` in HTML you render from PHP, no external CDNs. Page data travels in `<script type="application/json" id="mphp-props">` (allowed). If you need a third-party origin, add it in `core/Middleware/SecurityHeaders.php`.
- **CSRF**: all non-GET requests need the token. The shell adds `<meta name="csrf-token">`; `api()` and `Form` send it as `X-CSRF-Token`. Requests with an `Authorization` header skip CSRF (token APIs). For plain HTML forms add `<input type="hidden" name="_token" value="<?= e($csrf) ?>">`.
- **Secrets**: `.env` is git-ignored. Read config with `env()` only inside `config/*.php`; elsewhere use `Config::get('app.x')`. Encrypt with `Crypto` (needs `APP_KEY`); hash passwords with `Passwords::hash/verify`; never use `md5`/`sha1` for secrets, never `rand()`.
- **Uploads**: `Uploader::store($_FILES['f'], 'image'|'pdf'|'audio'|'video', maxBytes)`. It sniffs the real type and renames the file. Do not trust `$_FILES['f']['name']` or `type`.
- **Errors**: `throw new HttpException(404, 'Message safe to show')`. Any other exception shows a generic 500 in production and the debug page when `APP_DEBUG=true`.
- **Debug bar**: with `APP_DEBUG=true` HTML pages get a bar (route, time, SQL list, repeated-query warning) and every response gets `Server-Timing`. Use it to spot N+1 queries. Never enable `APP_DEBUG` in production.
- **Generated files** (`resources/js/generated/*`, `public/build`, `storage/cache/routes.php`) are outputs. After changing routes run `types:generate` (and `routes:clear` if a stale cache exists).
- **PHAR mode**: code is read-only inside `mphp.phar`; `.env` and `storage/` live in the directory it runs from (`MPHP_HOME`). Use `App::$dataPath` (not `basePath`) for anything written at runtime, and `scandir` (not `glob`) to list files in framework code.

## Testing

Tests use Pest. Helpers in `tests/Pest.php`:

- `testApp()`: a booted app on a fresh in-memory SQLite database, migrations applied, Vite stubbed, throttle isolated.
- `call($app, 'POST', '/api/posts', ['title' => 'x'])`: sends a request through the whole kernel and returns a `Response`; unsafe methods get a valid CSRF token automatically, pass `csrf: false` to test rejection.
- `httpStatus(fn() => ...)`: `[status, headers]` of the `HttpException` thrown by a closure.
- `tempDir()`: a throwaway directory.

Test the behaviour the user sees: status codes, JSON bodies, validation errors (422), 404/405, mass-assignment protection, CSRF rejection. Put framework unit tests in `tests/Unit`, HTTP flows in `tests/Feature`. Set `$app->config->set('app.debug', true)` to test debug-only behaviour.

## Definition of done

1. `vendor/bin/pest` passes.
2. `php bin/mphp types:generate` was run and the generated diff is committed.
3. `npm run check` reports 0 errors and `npm run build` succeeds.
4. No secret, `.env`, `storage/` file or `public/build` output is committed.
5. New input is validated through a `FormRequest` or `Validator`; new SQL goes through `QueryBuilder`; new output is escaped.

## Do not

- Edit anything under `resources/js/generated/` by hand.
- Add a runtime Composer dependency without a strong reason: the zero-dependency deploy is a feature.
- Put code, `.env` or `storage/` inside `public/`.
- Weaken the CSP, disable CSRF globally, or catch-and-hide exceptions to make a test pass.
- Add Node-only runtime requirements (server-side rendering, long-running Node processes).
